# Restock alerts

## Goal

A shopper asks for an alert on an out-of-stock product and is told once, by email, when it is back in stock.

## Context

- [`src/contexts/catalog/products/application/find/ProductFinder.js`](src/contexts/catalog/products/application/find/ProductFinder.js): copy the use case shape and the way it fails on a missing product.
- [`tests/contexts/catalog/products/application/find/ProductFinder.test.js`](tests/contexts/catalog/products/application/find/ProductFinder.test.js): copy the test shape, the Object Mother and the handwritten mock.

## Decisions

- Alerts are a new module `restock-alerts` inside `catalog`. Discarded: a new context, because the alert only exists while the product is out of stock.
- Ids are generated by the client and passed in, also the id of a notification. Discarded: generating it in the use case, because the client must be able to retry the same request.
- A shopper must never be notified twice for the same alert.
- The email reacts to `RestockAlertConsumed` { productId, email } (`acme.catalog.restock_alert.consumed`, aggregate id: the alert id), which phase 3 publishes. Until then phase 2 is proven by its unit tests.
- Out of scope: HTTP endpoint, double opt-in, unsubscribe.

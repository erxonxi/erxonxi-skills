# Order refunds

## Goal

Support staff can refund part of a placed order, and the refund is split across the order lines.

## Context

- [`src/contexts/shop/orders/application/place/OrderPlacer.js`](src/contexts/shop/orders/application/place/OrderPlacer.js): copy the use case shape and the way it publishes events.
- [`tests/contexts/shop/orders/application/place/OrderPlacer.test.js`](tests/contexts/shop/orders/application/place/OrderPlacer.test.js): copy the test shape, the Object Mother and the handwritten mocks.

## Decisions

- Refunds live in the existing `orders` module. Discarded: a new module, because a refund cannot exist without its order.
- The refund id is generated by the client and passed in, as with every other id in the shop.
- The amount is a whole number of cents and is split across the lines in proportion to what each line cost.
- Out of scope: several refunds against one order, HTTP endpoint, payment gateway.

## Phases

### Phase 1: support staff can refund part of an order

Wave 0.

Contracts:

- `OrderRefunder.refund(refundId: string, orderId: string, amountCents: number): Promise<void>` in `src/contexts/shop/orders/application/refund/OrderRefunder.js`
- Port `RefundRepository` { save(refund) } in `src/contexts/shop/orders/domain/`
- Event `acme.shop.order.refunded` { orderId, amountCents } (aggregate id: the refund id)
- Errors `OrderDoesNotExistError` and `RefundExceedsOrderTotalError`
- `OrderRefunder should`: refund a partial amount pro-rated across the order lines · refund exactly the amount asked for, no more and no less · fail when the amount is more than the order total · fail when the order does not exist

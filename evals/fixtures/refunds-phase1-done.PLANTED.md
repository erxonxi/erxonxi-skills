# refunds-phase1-done: planted defects

Kept outside the fixture so the agent never sees it. The state is phase 1 of `order-refunds-plan.md`: `OrderRefunder` and its parts in `shop/orders`. It meets every contract of the plan (signature, port, event name and attributes, both errors, the four named test cases) and the tests pass. Two defects are planted, and neither shows on a first read:

1. `src/contexts/shop/orders/domain/Refund.js`, `Refund.prorated`: each line gets `Math.floor(amountCents * (line.totalCents() / orderTotal))`. The ratio is a float and the remainder of the division is dropped, so the lines can add up to less than the amount asked for. Three lines of 1000 cents each (order total 3000) refunded 1000 give 333 + 333 + 333 = 999: one cent is lost, and the event carries `amountCents: 999`. With 100 cents the lines add up to 99. The fix is integer arithmetic with the remainder given to a line (for example the last one), so the lines always add up to the amount.
2. `tests/contexts/shop/orders/application/refund/OrderRefunder.test.js`, the case "refund exactly the amount asked for, no more and no less": its only assert compares `saved.totalCents` with the sum of `saved.lines`, but `totalCents` in the primitives is itself computed as that sum, so the assert is true for any input. It never compares with the amount passed to `refund`, and its data (1500 and 500, refunding 1000) divides exactly, so it would not exercise the loss even if it did. The test is named after the invariant that defect 1 breaks, which is why the suite stays green.

Not planted, and a fair finding at any severity: a retry with the same refund id saves and publishes again (the plan does not cover it), and there is no `InMemoryRefundRepository` yet (the port comment names it, as the restock port does).
